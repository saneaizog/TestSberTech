мне # ТЗ: Система аутентификации фотоплатформы

## Исполнители
- **srs-analyst**: Формирование и обновление технического задания
- **opencode**: Реализация системы аутентификации

## 1. Введение (цель, бизнес-ценность)

**Цель:** Реализация современной системы аутентификации и идентификации пользователей для фотоплатформы с поддержкой OAuth2 через Keycloak, Magic Link аутентификацией и корпоративным SSO.

**Бизнес-ценность:**
- Повышение безопасности через двухфакторную аутентификацию
- Снижение порога входа для корпоративных пользователей через Keycloak SSO
- Удобство доступа для мобильных пользователей через Magic Link
- Унификация профилей при множественных привязках OAuth2
- Соответствие enterprise-требованиям безопасности

## 2. Область работ (In/Out)

**In-scope:**
- OAuth2 интеграция с Keycloak (realm: sberTech)
- Множественные привязки OAuth2 аккаунтов к одному профилю
- Email+пароль аутентификация с JWT
- Magic Link аутентификация (5 минут, 3 попытки)
- 2FA через TOTP
- Сброс пароля через email
- Встроенные UI опции на форме входа
- Refresh токены
- Logout всех устройств
- API Rate Limiting

**Out-of-scope:**
- Аутентификация через биометрию
- SSO через SAML
- Enterprise SSO через Active Directory
- Социальные провайдеры (Google, Facebook, VK)
- Телефонная аутентификация
- LDAP интеграция
- KYC верификация

## 3. Термины и определения

| Термин | Определение |
|--------|-------------|
| Keycloak | Open Source Identity and Access Management решение |
| SberTech realm | Корпоративный realm в Keycloak для SberTech |
| SSO | Single Sign-On - единая точка входа для корпоративных пользователей |
| OAuth2 | Протокол авторизации для делегирования доступа |
| Magic Link | Временная ссылка для входа без пароля |
| TOTP | Time-based One-Time Password |
| JWT | JSON Web Token |
| Refresh Token | Токен для обновления access токена |
| Account Linking | Привязка нескольких OAuth2 аккаунтов к одному профилю |

## 4. Контекст и текущие ограничения

**Допущения:**
- Keycloak настроен и доступен по HTTPS
- Используется realm "sberTech" в Keycloak
- Email сервис для Magic Link и сброса пароля функционирует
- База данных пользователей уже существует
- Фронтенд готов к интеграции с новым Auth Service
- Корпоративные клиенты используют Keycloak как центральный IdP

**Ограничения:**
- Максимальное время ответа API: < 200ms
- JWT токен lifetime: 15 минут
- Refresh токен lifetime: 30 дней
- Magic Link: 5 минут срок действия, максимум 3 попытки
- Максимальное привязанных OAuth2 аккаунтов: 10 на профиль

## 5. Функциональные требования

**FR-001: OAuth2 аутентификация через Keycloak**
- Приоритет: Must
- Пользователь может войти через Keycloak OAuth2
- Используется realm "sberTech"
- Система получает user info из Keycloak
- Автоматическая создание профиля при первом входе
- Критерии приемки:
  - Успешный редирект на Keycloak realm sberTech
  - Получение access токена и user info
  - Создание/обновление локального профиля
  - Возврат JWT токенов клиенту

**FR-002: Множественные привязки OAuth2 аккаунтов**
- Приоритет: Must
- Один профиль может иметь несколько привязанных OAuth2 аккаунтов
- Пользователь может привязывать/отвязывать OAuth2 аккаунты
- Основной email для уведомлений выбирается пользователем
- Критерии приемки:
  - Привязка до 10 OAuth2 аккаунтов
  - Отвязка без удаления основного аккаунта
  - Смена email для уведомлений
  - Отображение всех привязанных аккаунтов

**FR-003: Email+пароль аутентификация**
- Приоритет: Must
- Регистрация с email+пароль
- Валидация пароля: 8+ символов, цифры, спецсимволы
- Хеширование паролей bcrypt (salt rounds: 12)
- Критерии приемки:
  - Успешная регистрация/вход
  - Корректная валидация пароля
  - Хеширование без plain text

**FR-004: Magic Link аутентификация**
- Приоритет: Must
- Отправка Magic Link на email
- Срок действия: 5 минут
- Максимум 3 попытки на email за 15 минут
- Критерии приемки:
  - Magic Link действителен 5 минут
  - Блокировка после 3 попыток
  - Одноразовое использование ссылки
  - Логирование всех попыток

**FR-005: Двухфакторная аутентификация (2FA)**
- Приоритет: Should
- Настройка TOTP через QR код
- Запрос кода при входе
- Резервные коды восстановления
- Критерии приемки:
  - Генерация TOTP секретов
  - Валидация 6-значных кодов
  - 10 резервных кодов
  - Отключение 2FA

**FR-006: Управление токенами**
- Приоритет: Must
- Access токен: 15 минут
- Refresh токен: 30 дней
- Logout всех устройств
- Критерии приемки:
  - Автоматическое обновление токенов
  - Инвалидация refresh токенов при logout
  - Logout всех устройств

**FR-007: Встроенный UI для аутентификации**
- Приоритет: Should
- Форма входа с опциями: Email/пароль, Keycloak, Magic Link
- Адаптивный дизайн для мобильных устройств
- Индикация загрузки и ошибок
- Критерии приемки:
  - Все опции на одной форме
  - Редирект на Keycloak realm sberTech
  - Отправка Magic Link из UI
  - Валидация на клиенте

**FR-008: Rate Limiting и защита**
- Приоритет: Must
- 5 попыток входа в минуту на IP
- 10 запросов Magic Link в час на email
- Защита от brute force
- Критерии приемки:
  - Блокировка по IP/Email
  - HTTP 429 Too Many Requests
  - Логирование превышений лимитов

## 7. Данные и модели

### User Entity
```sql
users (
  id UUID PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255),
  email_verified BOOLEAN DEFAULT FALSE,
  totp_secret VARCHAR(255),
  totp_enabled BOOLEAN DEFAULT FALSE,
  backup_codes TEXT[],
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  last_login TIMESTAMP,
  login_count INTEGER DEFAULT 0
);
```

### OAuth2 Accounts
```sql
oauth_accounts (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  provider VARCHAR(50) NOT NULL, -- 'keycloak'
  realm VARCHAR(50) NOT NULL, -- 'sberTech'
  provider_user_id VARCHAR(255) NOT NULL,
  email VARCHAR(255) NOT NULL,
  access_token TEXT,
  refresh_token TEXT,
  expires_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (user_id, provider, realm, provider_user_id)
);
```

### Magic Links
```sql
magic_links (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  token VARCHAR(255) UNIQUE NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  used BOOLEAN DEFAULT FALSE,
  attempts INTEGER DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### Refresh Tokens
```sql
refresh_tokens (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  token_hash VARCHAR(255) UNIQUE NOT NULL,
  device_info TEXT,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### Rate Limiting
```sql
rate_limits (
  id UUID PRIMARY KEY,
  key VARCHAR(255) UNIQUE NOT NULL,
  count INTEGER DEFAULT 1,
  window_start TIMESTAMP DEFAULT NOW(),
  type VARCHAR(50) NOT NULL -- 'login', 'magic_link'
);
```

## 8. Интеграции и API

### Keycloak OAuth2 Integration
**Realm:** sberTech
**Endpoints:**
- Authorization: `GET /auth/realms/sberTech/protocol/openid-connect/auth`
- Token: `POST /auth/realms/sberTech/protocol/openid-connect/token`
- User Info: `GET /auth/realms/sberTech/protocol/openid-connect/userinfo`

**Flow:**
1. Редирект на Keycloak realm sberTech
2. Получение authorization code
3. Exchange code для access/refresh tokens
4. Получение user info
5. Создание/обновление локального пользователя

**Error handling:**
- Access denied: HTTP 403
- Invalid token: HTTP 401
- Rate limit: HTTP 429
- Retry: 3 попытки с exponential backoff

### Auth Service API
```
POST /api/v1/auth/register
POST /api/v1/auth/login
POST /api/v1/auth/oauth/keycloak/url
POST /api/v1/auth/oauth/keycloak/callback

POST /api/v1/auth/magic-link/verify
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
DELETE /api/v1/auth/logout-all
GET /api/v1/auth/me
POST /api/v1/auth/2fa/enable
POST /api/v1/auth/2fa/disable
GET /api/v1/auth/oauth/accounts
POST /api/v1/auth/oauth/link

```

## 10. Безопасность и права доступа

**Токены:**
- JWT: RS256 подпись, 15 минут
- Refresh: 30 дней, revocation list в Redis
- Device fingerprinting

**Валидация:**
- Email: RFC 5322
- Пароль: 8+ символов, цифры, спецсимволы
- Rate limiting: 5/мин IP, 10/час email

**Защита:**
- bcrypt (salt rounds: 12)
- CSRF токены
- Content Security Policy
- Brute force защита
